their own Google Fonts `@import`), and licensed under the SIL Open

permitted).

## Raster exports — `brand/logo/png/` and `brand/logo/webp/`

All rasterised from `te-monogram-full-colour.svg` — the compact mark,
built from plain geometry with no font dependency, so every export is
pixel-accurate with no font-substitution risk (unlike a wordmark-based
raster, see the note in `BRAND_GUIDELINES.md` §7).

**Total: 11 PNG + 8 WebP = 19 raster files.**

**PDF:** not generated. No PDF-generation tool exists in this
environment without adding a heavy dependency (a full headless-browser
print pipeline) for a single format. The SVG masters are print-ready
as-is — any print vendor or design tool (Illustrator, Affinity,
Inkscape) can open an SVG and export a press-ready PDF directly; this
is a standard one-step action for whoever prepares the final print
file (who will also need to convert text to outlines at that point —
see `BRAND_GUIDELINES.md` §2.5).

## Verification performed

- The font-free monogram was checked visually at 512px and 32px (both
  read cleanly — screenshots taken during production, not just
  assumed).
- The text-based lockups (primary horizontal, stacked, wordmark) were
  checked in a live, internet-connected browser and confirmed to
  render in genuine Playfair Display (not a fallback serif) — the
  embedded `@import` fix that made this work is documented in
  `DECISIONS.md`.
- A CSS specificity bug in the verification harness itself (not the
  logo files) was found and fixed during this check — see
  `DECISIONS.md` for detail, kept for transparency about what was
  actually tested versus assumed.

## Regeneration

Run `node build-logos.mjs` from `brand/` (requires `npm install` once,
already done — see `brand/package.json`). The script is deterministic:
running it again reproduces byte-identical output.
